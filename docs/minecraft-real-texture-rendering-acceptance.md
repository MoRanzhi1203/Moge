# Minecraft 真实贴图画布渲染与材料匹配验收报告

- 验收日期：2026-11-15
- 测试作品：`E:\画稿\原图\J4.jpg`（1000×1000 人物画）
- 场景：Java 1.20.1、64×64 网格、真实资源
- 验收方式：真实 GUI 处理 + 画布 QImage 逐像素比对，不以“PNG 存在/SHA 通过”代替渲染验证

## 1. 实际渲染链审计

| 环节 | 实测值 |
|---|---|
| GridDocument | 64×64 labels，材料条目来自当前结果 |
| RenderResult | `java 1.20.1`，候选随筛选变化（15 / 29 / 348） |
| 材料 ID | 如 `white_terracotta`、`red_glazed_terracotta`、`white_stained_glass` |
| 纹理路径 | `%LOCALAPPDATA%\Moge\resources\textures\<sha256>.png` |
| PNG 解码 | `cv2.imdecode` → BGRA/RGBA → `INTER_NEAREST` 缩放至 16×16 |
| 画布渲染器 | `document.render("solid")` 或 `render_textured`，QImage 尺寸分别为 64×64 / 1024×1024 |
| 预览模式 | 状态栏 `预览：纯色` / `预览：真实纹理` |
| 最终输出 | `GridCanvas._image`（QImage），测试直接读取 `canvas.image()` 比对 |

每个单元格的渲染分支：

- 纯色：`render_grid` 直接写入材料 `entry.rgb`。
- 真实纹理：`render_textured` 按 `entry.meta["texture_path"]` 读取当前版本 PNG，最近邻放大 16×16 平铺。
- 缺少纹理：切换前检查全部已用材料；缺失则拒绝切换并提示，不会静默以纯色冒充真实纹理。

## 2. 预览切换修复

- 状态栏新增固定标签：
  - `预览：纯色`

## 4. 材料匹配修复

### 4.1 分类错误修复

带釉陶瓦此前被分类为 `terracotta`，导致“仅普通陶瓦”实际上包含带釉陶瓦。已修复 `_guess_category` 的匹配顺序（`glazed` 优先），并重建全部 9 个版本索引。

| 筛选 | 修复前候选 | 修复后候选 |
|---|---:|---:|
| 普通陶瓦 | 27（混入带釉） | **15**（仅普通） |
| 陶瓦 + 带釉 | — | **29** |

### 4.2 匹配策略

新增四种策略：

| 策略 | 说明 |
|---|---|
| 感知色差优先（默认） | CIEDE2000；在 2.0 ΔE 容差内用纹理复杂度做平局裁决 |
| 纹理一致性优先（实验） | ΔE + 复杂度差 + 亮度标准差差 |
| 轮廓细节优先（实验） | 边缘单元优先高复杂度，平坦单元惩罚复杂纹理 |
| 均衡优化（实验） | 颜色、复杂度、亮度的折中 |

同时：

- 带釉陶瓦在非默认策略中使用“均值/中位色取较近者”，避免仅用平均 RGB。
- 纹理特征来自 `textures` 表的复杂度、亮度标准差、中位色，并随方块面传入匹配。

### 4.3 实测对比（64×64 人物画）

| 场景 | 策略 | 平均 ΔE00 | P95 | 特征误差 |
|---|---|---:|---:|---:|
| 陶瓦 | 感知（默认） | 16.06 | 21.03 | 0.084 |
| 陶瓦 | 纹理/轮廓/均衡 | 16.04 | 21.02 | 0.084 |
| 陶瓦+带釉 | 感知（默认） | **12.84** | **15.75** | 0.619 |
| 陶瓦+带釉 | 纹理 | 16.23 | 21.03 | 0.095 |
| 陶瓦+带釉 | 轮廓 | 13.36 | 17.93 | 0.696 |
| 陶瓦+带釉 | 均衡 | 15.37 | 21.02 | 0.353 |
| 全部方块 | 感知（默认） | **3.56** | **7.67** | 0.067 |
| 全部方块 | 纹理 | 3.75 | 8.28 | 0.038 |
| 全部方块 | 轮廓 | 3.61 | 7.83 | 0.055 |
| 全部方块 | 均衡 | 3.67 | 8.06 | 0.046 |

默认策略加入纹理平局裁决前后：

| 场景 | 平均 ΔE00 | P95 | 特征误差 |
|---|---|---|---|
| 陶瓦+带釉 | 13.32 → **12.84** | 17.62 → **15.75** | 0.709 → **0.619** |
| 全部方块 | 3.78 → **3.56** | 8.60 → **7.67** | 0.126 → **0.067** |
| 仅陶瓦 | 16.06 → 16.06 | 21.03 → 21.03 | 0.084 → 0.084 |

结论：默认策略在加入平局裁决后稳定改善纹理一致性，同时不牺牲陶瓦颜色指标；其余三种策略在部分场景改善特征误差但显著牺牲颜色，因此**保留为实验选项，不设为默认**。

### 4.4 画质损失提示

- 候选 < 80 或平均 ΔE00 > 8 或 P95 > 15 时：
  - 统计页显示红色“画质评估”；
  - 状态栏追加“画质警告：当前材料集色差较大”；
  - `render_limitations` 列出限制（材料集过小、染色方块、半透明方块）。
- 陶瓦场景平均 ΔE00 16.06，明确提示画质损失，不再静默生成偏色结果。

## 5. 特殊方块

- 带釉陶瓦：按 `visible_face` 选择面；图案复杂，纯色预览仅显示均值，真实纹理预览显示完整图案；默认匹配在色差容差内优先低复杂度候选，避免图案块铺满平坦区域。
- 透明方块：仍保留在候选中，但统计注明“按不透明平均值参与匹配”。
- 生物群系染色方块：统计注明“预览显示灰度底，未应用 tint”。
- 多面纹理：按 `block_state` + `visible_face` 从数据库读取对应面；逐格记录 face 字段。

## 8. 报告必须回答的问题

1. **真实人物画是否使用了原版 PNG？**
   是。纹理预览画布为 1024×1024（64×64 单元 ×16），逐格与 `resources/textures/<sha256>.png` 的最近邻放大结果完全一致。

2. **哪些单元格经过逐像素验证？**
   共 24 个单元：陶瓦 5 个、陶瓦+带釉 7 个、全部方块 12 个，坐标与 SHA-256 见 CSV。重点是 `white_terracotta`(0,0)、`red_glazed_terracotta`(49,34)、`white_stained_glass`(25,0)、`polished_diorite`(39,5) 等。

3. **纯色与纹理预览的实际差异是什么？**
   普通陶瓦纹理接近均值，单格平均差 1.5–1.9；带釉陶瓦因图案，差值 20–57；`white_stained_glass` 差 0（纹理本身纯色）；全部方块中 `polished_diorite` 等晶体纹理差 24.6。切换只改变渲染，不改变统计与网格。

4. **当前选中模式是否在 UI 中明确显示？**
   是。工具栏选中项为蓝底白字加粗，状态栏固定显示“预览：纯色 / 预览：真实纹理”，二者互斥。

5. **陶瓦模式偏色的主要原因是什么？**
   候选只有 15 种普通陶瓦，色彩空间窄；陶瓦纹理大面积均匀、明度高，无法覆盖人物皮肤与阴影的连续色阶（平均 ΔE00 16.06）。这不是纹理渲染错误，而是材料集限制；加入带釉陶瓦后平均降至 12.84，但图案复杂度上升。

6. **材料匹配优化后是否确实改善画质？**
   默认策略加入复杂度平局裁决后：全部方块平均 ΔE00 3.78→3.56、P95 8.60→7.67、特征误差 0.126→0.067；陶瓦+带釉平均 13.32→12.84、P95 17.62→15.75。颜色与纹理一致性均有稳定改善。其余三种实验策略未在全部场景稳定优于默认，故不设为默认。

## 9. 剩余问题

1. 生物群系 tint 仍未应用（草、树叶、水呈灰度底）。
2. 带釉陶瓦图案在 16×16 单元内可完整显示，但匹配仍按单元颜色/复杂度，无法按图案走向对齐。
3. 陶瓦类筛选的材料集过小，画质警告无法通过算法消除，只能建议放宽筛选。
4. 实验策略在全部方块场景耗时 3.5–4.2 秒，默认策略约 2 秒；后续可再优化批量 ΔE 计算。
